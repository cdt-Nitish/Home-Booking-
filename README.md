# Home Rental App

An Express and EJS application for browsing home listings, saving favourites, signing in as a host or guest, and uploading listing images. Listing and user records are stored in MongoDB.

## Run the application

1. Install dependencies:

   ```sh
   npm install
   ```

2. Configure a valid MongoDB connection URI in `DB_Path` in `app.js`. The same URI is used for Mongoose data and the MongoDB-backed session store.
3. Start the server and Tailwind watcher:

   ```sh
   npm start
   ```

   The app listens at `http://localhost:7000`. The `tailwind` script can also be run separately to rebuild `public/output.css` from `views/input.css`.

## How the files connect

```text
Browser request
  |
  v
app.js
  |-- static files, form parsing, image upload, session and login/host checks
  |-- authRouter  --> authController  --> User model
  |-- storeRouter --> storeController --> Home and User models
  |                                      |
  |                                      +--> EJS views in views/auth and views/store
  |-- hostRouter  --> hostController  --> Home model + uploads/
  |                                      |
  |                                      +--> EJS views in views/host
  |
  +--> errors.pageNotFound --> views/404.ejs
```

Controllers receive requests from routers, perform database or file operations, and either render an EJS view or redirect. The views include shared files from `views/partials` for the page head and navigation. `app.js` connects to MongoDB before starting the HTTP server.

## Request flows

### Signup and login

`authRouter.js` sends `/signup` and `/login` requests to `authController.js`. Signup validates the submitted fields, hashes the password, and saves a `User`. Login finds the account by email, compares the password hash, and stores the user's ID and account type in the session. `app.js` loads session state and sets `req.isLoggedIn` before the routers run; the navigation partial uses those values to show the appropriate links. The `/host` middleware also requires a logged-in user with the `host` account type.

### Browsing and favourites

`storeRouter.js` directs home and favourite URLs to `storeController.js`. The controller reads listings through `models/home.js` and renders templates in `views/store`. A user's favourite IDs are stored on their `User` document in `models/user.js`; the favourites page populates those IDs to display the matching homes.

### Host listings and image uploads

Host forms in `views/host/edit-home.ejs` submit multipart form data to `/host/add-home` or `/host/edit-home`. Multer is configured in `app.js` to accept the `image` field and save supported image files in `uploads/` with generated filenames. `hostController.js` stores the resulting path in the `Home` document. The edit flow keeps the existing image when no replacement is uploaded. Listing image URLs are served from the uploads directory by the static routes in `app.js`.

### House-rules download

The `/rules/:homeId` route calls `storeController.getHouseRules`, which checks the session and sends `rules/rules.pdf` as a download. The route parameter is part of the URL; the current handler sends the same rules PDF for each home.

## Routes at a glance

| Method | URL | Purpose |
| --- | --- | --- |
| GET | `/` | Landing page |
| GET | `/homes` | Browse listings |
| GET | `/homes/:homeId` | Listing details |
| GET | `/bookings` | Bookings page |
| GET | `/favourites` | Current user's favourites |
| POST | `/favourites` | Add a favourite |
| POST | `/favourites/delete/:homeId` | Remove a favourite |
| GET | `/rules/:homeId` | Download house rules |
| GET, POST | `/login`, `/signup` | Login and registration forms/actions |
| POST | `/logout` | End the current session |
| GET, POST | `/host/add-home` | Show or create a listing |
| GET | `/host/host-home-list` | Show listings |
| GET | `/host/edit-home/:homeId` | Show the edit form |
| POST | `/host/edit-home` | Save listing changes |
| POST | `/host/delete-home/:homeId` | Delete a listing |
